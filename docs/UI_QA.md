# 本地界面验证 · v0.2

2026-10-31，在助手云端 Chrome 中，通过托管的本地预览完成。没有使用用户电脑、Docker、真实客户、支付或模型 API；没有网站部署或 GitHub 操作。

## 实际操作与观察

| 检查 | 浏览器中观察到的结果 |
|---|---|
| 初始桌面布局 | 中文说明、模拟警示、账户、需求表单、推进区和账本正常显示；桌面截图已人工检查 |
| 报价 | 两条合成商品报价 20，版本增加 1，无积分转移 |
| 双击付款 | 仅一笔 20 积分进入托管，版本只增加 1 |
| 错误价格交付 | 卖家产生 4 积分成本，保持待验收，不能直接取消 |
| 独立验收 | 识别 `product price changed`，要求返工，保留托管本金 |
| 正常返工并验收 | 累计成本 8，卖家本单净变动 +12，买家 80 / 卖家 42 / 成本方 8 / 托管 0，总量 130 |
| 关闭服务后重启并刷新 | 相同实验、版本 6、四笔划转和同样余额；没有重复交付或结算 |
| 重置对话框取消 | 实验标识、版本与四笔划转不变；焦点返回重置按钮 |
| 两个标签页 | 第一页创建订单后，第二页过期请求被拒绝，刷新到新版本，无第二个重复订单 |
| 浏览器 Back/Forward | 仅切换选中的订单；版本 7 和四笔划转不变 |
| 付款后取消 | 本金退回，新增付款/退款两笔，状态已取消 |
| 服务重启后的旧会话令牌 | 返回拒绝，原请求键保留，刷新令牌；重新打开页面仍能显式重试同一请求，报价只增加一次 |
| 连续两次卖家崩溃 | 两次成本共 8 保留；独立验收拒收并退本金，历史错误仍可见 |
| 确认新实验 | 新实验版本 0、零笔划转、初始积分 130；数据库中旧实验未删除 |
| 旧标签页对新实验操作 | 旧实验标识被拒绝；新实验仍为版本 0、无订单 |
| 断开本地服务后发请求 | 显示结果不确定，保留原请求，其他交易操作锁定 |
| 恢复服务并重新打开页面 | 相同待处理请求标识仍在；显式重试后只有一条报价命令、零笔划转 |

## 修复与边界

- QA 中修复了 403 被当作普通拒绝而丢弃待确认请求身份的问题：现在保留请求，刷新令牌，由用户显式重试。
- 普通冲突提示不再声称“此前肯定未执行”，而要求检查最新流水。
- 请求及读取 JSON 都有 15 秒超时；原请求身份在超时后保留。浏览器已验证立即断线恢复，但未人工等待完整 15 秒挂起响应；该时限经过代码检查，不宣称已完成故障代理延迟测试。
- 移动端布局有响应式 CSS，但本轮未做真实手机/移动视口浏览器验证；不宣称跨浏览器可访问性或手机体验已完成认证。
- 本次模拟了正常服务重启、断线和数据库事务失败；没有做操作系统断电或硬件损坏实验。
- 截图仅用于内部布局 QA，没有把浏览器截图保存为交付文件。测试运行数据是本地临时合成数据，不纳入版本控制。
