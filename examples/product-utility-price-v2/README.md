# V2功能、使用痛点与价格：有限虚拟顾客实验

**不是文案重写。** 新增假设保冷结构、盖锁和携带环，同时增加重量与高度，观察不同虚拟处境下是否值得换杯。所有性能、尺寸和合成出库记录均为虚构设定，不是实物测量、真实品牌能力、认证或真人验证。

## 实际结果，含失败

六个独立顾客请求，取得五份回答；另有三份独立卖家与三份同顾客验收回答，共12次请求、11份实际原文。

- 旧瓶已满足者，V2价16和24：继续免费旧瓶。保冷/盖锁没有解决其现有问题，增重和高度不划算。
- 旧瓶已满足者，V2价32：模型容量错误，没有顾客回答。原始错误保存于 `failures.json`，遵守冻结规则不重试、不换模型。**这是系统缺失，不是不买。**
- 漏水/升温困扰者，V2价16/24/32：三者均选择V2。分别再询独立卖家，三者同意并承担交付费及预授权退款；实际执行模拟托管与交付后，同一顾客分别验收接受。
- 没有角色选择原杯。没有本轮实际退款，不能把退款回归测试当作这轮顾客结果。

最终三笔独立模拟分支（不是同一人连买三件）：

## 冻结设计与可比范围

协议 `protocol.json` SHA256：`92ed982380ffc4d071102dab923947da69be8f939f09dba84acedaa5ccf15405`。在角色调用前固定，时间见文件；哈希不独立认证冻结时间或模型身份。

两个画像共同条件：500ml需求、预算90、携带重量偏好≤250g、明天通勤。差异只有旧瓶现状和温度需要：一类旧瓶不漏且接受常温，另一类漏湿纸张、想喝凉水；后者仍可用塑料袋隔开纸张并接受常温，保留免费退路。

三个选项：
- 旧瓶0积分、500ml、35g，无保冷设计。
- 原杯32积分、500ml、220g，普通单层，假设防漏，无保冷。
- V2为同一固定产品，价格16/24/32。500ml、240g、68mm直径、230mm高、45mm杯口，假设盖锁和携带环；在虚构设定里正确锁盖正常通勤不漏，25°C环境、初始4°C水、装满闭盖6小时后≤10°C。这只是显式条件化的假设，**没有做过物理实验**。

各价格下V2除价格外字段逐字相同。原杯价格固定，V2在16/24时比原杯便宜，在32时同价；观察到的选择只针对这组人为选项，不能推广市场竞争力。

展示顺序用固定种子202611041703打乱循环拉丁顺序，每选项在计划六格的各位置出现两次；它不是模型采样种子。由于一格容量错误，**实际取得回答的五格不再完全位置平衡**。每个价格×画像只有一次，顺序和抽样差异无法从价格/需求效应中分离。三个痛点角色都选V2，不能据此估计价格弹性、真实转化率、最高愿付价，或断言画像差异具有因果效果。

## 模型与账本的分界

每名角色只允许读取自己分配的冻结提示，不可读取其他结果；买家各自新上下文，卖家另起独立上下文，验收续用本分支买家。当前对话模型家族、精确SKU及采样种子未核验。实际读取提示的包装指令仅限定单文件读取、禁止联网/写入，未改变选择目标。

买家选择购买和卖家接受都取得后，才调用既有Market执行quote/fund/deliver。交付和保冷观察都是预设合成环境，非新模型“实测”。`snapshots/` 保存验收前的托管状态，`report.json` 保存所有原文、缺失及最终账本。验收自由接受/退款/暂缓；本轮实际全部接受，不追加诱导问题来制造退款。

实际原文在 `responses/`，模板和每次具体提示在 `prompts/`。所有失败保留，不重试筛选。没有对外投放、真实支付、付费API或待批第三方测试。
